## Skryensya UI 0.0.3

The third release, still distributed as GitHub Release tarballs (nothing is published to npm). The package set is the same as 0.0.2.

### Breaking changes

- **Each appearance ships as its own stylesheet.** The `tactile`, `brutalist` and `frosted` rules (and Steps' `segments`) moved out of each component's sheet into `<component>.<value>.css`. Import the sheet for the value you use; without it, that value gets no paint. The hooks stay declared in the base sheet. Without any appearance the kit is about 13% lighter. Migration: `docs/migrations/0002-appearance-sheets.md`.
- **SplitButton becomes ButtonGroup**, and the weld moves to the group: Button's `weldStart`/`weldEnd` and Menu's `triggerWeldStart`/`triggerWeldEnd` are gone. Migration: `docs/migrations/0001-split-button-to-button-group.md`.
- ButtonGroup's default separator is inset, and `separator="none"` exists.
- FormField's `labelHidden` is renamed `labelVisuallyHidden`.
- Tag's `tone` no longer accepts `success`, `warning` or `danger`.
- CodePreview's copy button floats over the code; ColorPicker has a simpler panel.
- Input `sm` is 36px instead of matching `md`.

### New component

- **SearchField**: a search box whose value is whatever was typed, with a magnifier, a clear button and Escape to clear. `SearchField.form` adds a GET `<form role="search">` with a submit button. The input is an `sk-input`, so it takes Input's sizes, appearances and states.

### New in existing components

- **Segmented**: an icon before the words, icon-only options (icon plus visually hidden words), `fill` to take the container's width, and `iconLabel="tooltip"` to show an icon-only option's words in the kit's Tooltip. The chosen option now says `aria-checked="true"`.
- **Button**: `asChild` for a router Link with Button's chrome; `loading` is inline and busy, and `loadingText` can swap the text.
- **Input**: an `xs` size, `inputmode`, a `ghost` variant, it can sit inside a ButtonGroup, and Textarea's `autoSize`.
- **Carousel**: alignment, step, soft snap, edge padding, fading edges and a counter in place of dots.
- **Combobox**: `max`, and it takes Select's `options` and `aria-label` so moving from Select needs no rewrite.
- **Select** inherits FormField's id, `required` and description, and accepts `aria-label`/`aria-labelledby`.
- **Toasts**: `toastQueue` / `useToastQueue` for an imperative `toast()` with no provider.
- Also: Tag `disabled` and `Tag.toggle`; TagsInput clears every tag at once; Table sortable headers; Tabs without panels; Megamenu plain links and the current section; Lightbox plays video; Questionnaire sections and `onValuesChange`; Resizable absolute floors; TreeView `collapsible={false}`; Details `sm`; and new hooks for the slider thumb shadow, the avatar group ring, the tactile press tempo and the dialog exit duration.

### Tokens and accessibility

- Default borders are softened to just above WCAG's 3:1 for non-text contrast.
- High contrast, light: subtle borders go from 2.6:1 to about 4.8:1, and recessed surfaces are told apart from the page.
- Fixes for RTL arrows in Menubar, empty accessible names (Separator, Loader, Quote, Timeline), Accordion heading levels and container-based fallbacks in DescriptionList, Questionnaire and Timeline.

### Tooling

- The emitter no longer leaves a line break between an element at the edge of mixed content and its tag, which in a grid or flex container became an empty item.
- A contract's `compose` entry can take `when`, so a composed family's sheets load only for the option value that needs them.
- Eight dead anchoring hooks removed from the overlays that never read them.

### Documentation

- A styling hook playground on every component page.
- Beta components carry a notice that their options, markup or hooks may still change.
- The preferences panel and navbar are built only from kit components, with a GitHub link.

### Verification

- `pnpm check`
- Every tarball is opened and checked: its version, and that every file its `exports` name is inside it (`node scripts/release.ts verify`).
