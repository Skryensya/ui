## Skryensya UI 0.0.4

The fourth release, still distributed as GitHub Release tarballs (nothing is published to npm). Much of it comes from a vanilla consumer's migration (an Astro 4 + Vite 5 site on 0.0.3), and every fix from it lets that consumer delete a workaround. It also brings two new components, Magnifier and Gallery, and frameless Accordions.

### Breaking

- **Icons come from Iconify, installed by your project.** `@skryensya/icons-lucide`, `-phosphor` and `-material` are gone, and React has no default set any more. Install a set as a dev dependency (21 presets over 13 Iconify collections are mapped: Lucide, Phosphor and its weights, Material Symbols and its styles, Tabler, Heroicons, Remix, MingCute, Hugeicons, Fluent, Carbon, Iconoir, Bootstrap Icons, Material Design Icons), run `skryensya icons <set>` to write `src/icons.ts` and `src/icons.css` with only the roles the components ask for, and bind it (`<IconSetProvider set={icons}>`, `mountIcons(document, icons)`). The rest of the collection never reaches the bundle. Any other Iconify set works with your own map through `iconSetFromIconify` in `@skryensya/core/iconify`. Recipe: [docs/migrations/0003-icons-from-iconify.md](../migrations/0003-icons-from-iconify.md).

- **Badge is shorter**, with no change to its API: 20px tall (18 at `sm`, 16 at `xs`) instead of 28, so it no longer reads as a Tag or a button. Its edge is a hairline in the text colour; in dark mode the fill is that colour, translucent, and the neutral badge is gray. Digits are tabular. Check layouts that relied on the old height.

### New components

- **Magnifier**: a round glass lens that follows the pointer over an image or a canvas and shows it larger, with the bend and the rainbow edge of real glass (WebGPU; a plain zoomed circle without it). Whole up to the picture's corners, it shrinks once the pointer leaves and closes on its own; holding the button grows it, and on touch a held finger magnifies while a swipe still scrolls. Reduced motion turns its springs off. `zoom`, `dispersion` (`subtle` or `strong`) and `filter` (clear, or red, green, blue, cyan, magenta or yellow glass); hooks for its size, background past the picture and shadow. It paints above the whole page on the new `--z-pointer` layer. Not for video: the picture moves the detail away from under the lens.
- **Gallery**: one large photo and thumbnails that choose it. The thumbnails are a native radio group and CSS decides which photo shows, so it works without JavaScript and is the same DOM in React and HTML. `placement` puts them under the photo, over it, or in a column beside it. Each view takes an ImageFrame or a Magnifier, and views that are `Lightbox.Trigger`s open the viewer on the whole gallery, in step with it.

### Fixes

- **Anchored boxes stay put with newer Zag versions.** With `@zag-js/svelte` 1.47 or later, `normalizeProps` hands `style` over as a Svelte attachment under a Symbol key, and the Vanilla runtime only read string keys. No machine style reached the DOM: without an inline `position`, `.sk-anchored`'s `fixed` won over coordinates measured for `absolute`, and menus, selects and tooltips drifted by the scroll offset (an account menu opened about 900px below its trigger). The runtime now runs that attachment. The kit's own tests did not see it because the repo pins 1.43.3.
- **Tooltip** uses `strategy: "fixed"` end to end, like the `.sk-anchored` stylesheet (Segmented's tips too).
- **Vanilla mounts without `svelte/internal/flags/legacy`.** `Imperative.svelte` (Megamenu, Toast, Button, Segmented, CommentThread and the other enhancers without a machine) and `Combobox.svelte` compiled in legacy mode, which throws unless the consumer imports that flag. Both compile in runes mode now.
- **Vanilla pins the Svelte it compiles with.** Compiled Svelte calls `svelte/internal/client`, which changes between minor versions: under the old `^5.56.7` range a consumer got 5.59 and the Carousel threw at mount (`Cannot read properties of undefined (reading 'call')`). `svelte` is now an exact dependency, checked against the compiler by a test.
- **Vanilla needs no bundler setting.** `@zag-js/svelte` ships runes source (`$effect` in `machine.svelte.js`), so a consumer without the Svelte plugin got `ReferenceError: $effect is not defined` from `mountComponentsWithIcons`. The release now compiles it into `dist/vendor/`: no Svelte plugin and no `svelte` resolver condition.
- **Marquee**: keyboard focus inside the strip turns the edge fade off and slides the paused track just enough to show the focused item, never onto the hidden copy. The fade returns when focus leaves.
- **Menu**: a theme with pill controls (`--radius-control: 999px`) no longer makes the panel and its rows capsules: their radius follows the control radius but never exceeds `--radius-surface`. Nothing changes with the default radii.
- **Marquee** reads its cadence in `ms` or `s`. The minified CSS ships it in seconds (`.96s`), so the strip ran about 1000× too fast.
- **Tabs**: a wide panel no longer pushes the horizontal tabs past a narrow screen (`grid-template-columns: minmax(0, 1fr)`).
- **Toast** pauses its auto-dismiss while the pointer is over it or focus is inside it, and resumes with the time it had left (WCAG 2.2.1).
- **Footer** no longer stretches to its container's height inside a flex column.
- **NavList**: a `<button>` row keeps the list's font size and weight instead of its parent's.
- **Focus rings are drawn whole** where a clipping container used to cut them: ExpandableTile's trigger, Details' summary, Tabs, Menubar, NavList, Breadcrumb, OTP input and TreeGrid rows. In a scrolling OTP row, the focused segment comes into view.
- **Tabs** no longer make the page jump on load: before the script mounts, only the panel that starts selected shows (without JavaScript every panel still shows).
- **Toast** is exactly its region's width; the dismiss button no longer sticks out and gets cut.
- **Select**: `select.css` no longer aborts a Vite build (lightningcss could not parse the picker's `::-webkit-scrollbar` rules); it uses `scrollbar-width` and `scrollbar-color`.
- **Megamenu** always opens below the bar, instead of flipping above it off screen.
- **Calendar and DatePicker**: on narrow screens a range calendar shows one month at a time with swipe snapping, and the range popup is centred below the field.
- **Vanilla**: a component whose markup is removed and put back (a re-render, a Storybook story or container switch) mounts again instead of staying dead.
- **Visually hidden**: a revealed `sk-visually-hidden` control is `position: relative`, so an `sk-button` skip link keeps its state layer on itself.

### New in existing components

- **Accordion**: `variant` picks the shape. `framed` is the one there was; `seamless` is titles, a plus or minus and space only; `divided` adds a hairline between sections; `separated` makes each section its own card. Only `framed` takes an `appearance`.
- **Lightbox**: `magnifier` adds a toggle to the zoom bar that puts a Magnifier lens over the photo; with it on, the mouse no longer drags the photo. The zoom buttons are + and − now.
- **Calendar and DatePicker**: ranges show two months, side by side or stacked, and the range picker takes both dates; `numOfMonths` switches back to one.
- **SearchField**: in `SearchField.form` the field and its button are one joined control.
- **Tabs**: `listPlacement: after` puts the strip under the panels and `wrap` breaks it onto rows; the DOM order, and so the keyboard, stays the same.
- **ImageFrame**: a `4/5` aspect, and `frameElement="span"` for a frame inside a button or a label.
- **Canvas**: smoother pan and zoom (one write per frame), pinch in desktop Safari, double click to zoom, a glide after a fast drag and a minimap while zoomed. Annotation's canvas gets the minimap too.
- **CommandPalette**: a one-letter typo still finds the destination, and the host can list recent pages first (`sk:commandpaletterecents`).
- **NavList**: `setNavListGroups(nav, open)` opens or closes every collapsible group at once.
- **ProgressiveCarousel**: `--sk-carousel-progressive-step` and `-hover` set its timings.
- **Icons**: new roles `favorite`, `expand-all` and `collapse-all`, a mark per kit component, and 24 optional brand logos (`skryensya icons <set> --brands`). An icon with `hidden` is actually hidden.
- **Megamenu**: the panel's position can be configured with four optional attributes on `[data-sk-megamenu]`, read at mount: `data-anchor="<selector>"` (an ancestor first, else the document; no match falls back to the root and warns in dev), `data-placement` (`block-end`, the default; `block-end-start`; `block-end-end`), `data-offset="<px>"` and `data-match-width`. Without them the panel is placed exactly as before. Vanilla and React.
- **CurveCarousel** (new, `Carousel.curve`): the slides on a wheel, `curve="convex"` seen from outside (the front slide nearest, the sides going back round the cylinder) or `curve="concave"` from inside (the front slide farthest, the sides wrapping towards you), for a hero rather than a shelf. Five slides in view on a desktop. Drag it and it keeps turning with momentum until it rests on a slide, without end (`infinite`, `momentum`, both on by default). A flat stepper instead of prev/next, which shows the time left under `autoplay`. `curveStrength` sets how much the ends grow or shrink, `bend` curves each picture (the wide-lens look), `fade` dissolves the sides. Keyboard: the stepper is one Tab stop and the arrows walk the slides (the focus follows), hidden slides leave the Tab order, changes are announced. No flat first frame: the wheel appears built; in Vanilla it loads its own module, without Svelte or Zag. `tall` gives portrait 9:16 slides, `focus` one large landscape 16:9 slide, a curved screen with `bend`, its neighbours wrapping round the sides. Its own engine in core (`connectCurveRing`), shared by both bindings; without JavaScript it is a centred snap scroller. Its own docs page.
- **ProgressiveCarousel** (new, `Carousel.progressive`): a circular carousel of progressive widths. The active slide comes first, its title on the picture, then three that shrink and the narrowest strips; its text, action and prev/next sit underneath. Moving on, the active slide leaves on the start side, the rest move up and widen, and a new one comes in on the end side, in one continuous move. The large slides stand 8px apart, the narrowest strips half that. Hovering any slide widens it in proportion to its size; the main picture covers its slide and a strip's picture stays centred as it opens. Narrow, it is a plain carousel you swipe. Prev/next, the arrow keys, a swipe or a click on a strip; the strips' content leaves the Tab order. Its own engine in core (`connectProgressiveTrack`) and its own Vanilla module; its own docs page.
- **Carousel**: `defaultPage`, the page it opens on.
- **Tabs**: outlined or filled tabs from tokens: `--sk-tabs-trigger-border-width` and `-border-color` (a border open on the rail side), `--sk-tabs-trigger-selected-bg` and `-selected-border-color`, and `--sk-tabs-list-border-width` for the rail. Defaults leave tabs as they were.
- **Select** (Vanilla): writing `data-value` after mount selects that item and fires `sk:selectvaluechange`.
- **Phone**: `@skryensya/phone` ships in the release like the other packages, so Input's `format="phone"` setup installs from its tarball.
- **Menu**: `--sk-menu-max-block-size`, how tall the panel grows before it scrolls inside itself. The default is unchanged. Breadcrumb's collapsed menu takes it too.

- **CLI**: `skryensya add <names> --icons <set>` also installs `@iconify-json/<set>` and writes `src/icons.ts`/`.css`, so a project starts in one command. `add` then prints the exact setup for the binding (bind the icon set; in Vanilla, `mountComponentsWithIcons(document, icons)`) until the sources contain it. It no longer tells Vanilla users that `import "@skryensya/vanilla/auto"` mounts anything (it does not), and the printed snippets avoid top-level `await`, which Vite's default build target rejects.
- **Combobox**: default labels in English, like the rest of the kit (`No results.`, `Clear selection`, `Show options`, `Selected values`, `Remove <item>`).

### For agents

- **A skill for building with the kit**, shipped inside `@skryensya/core` and installable with `npx skills add Skryensya/ui --skill skryensya-ui`. It routes between the MCP and an offline path, and ends every task with a review, a typecheck and the agent test.
- **The docs as Markdown in the package**: `@skryensya/core/docs` has `llms.txt`, `choose.md` (the person needs to → use, one row per signature) and one page per family, rendered from the contracts with an emitted React and HTML example each. They match the installed release.
- **`skryensya validate` and `skryensya review`**: the CLI checks a usage tree and prints its React and HTML, or reviews a whole page, from the same code as the MCP's `validate_ui` and `review_ui`.
- **`@skryensya/core/agent`**: an agent reads a page's kit components with `snapshot`, finds them with `query` and changes them with `act`, by name, in React and Vanilla alike. `data-agent-confirm`, `data-agent-secret` and `data-agent-hidden` put a person in the loop; `registerTools` offers the three tools to the browser's agent through WebMCP.
- **`review_ui` checks three more things**: a form control with no name (`control-named`), a role the kit ships a component for put on something else (`hand-rolled-widget`), and, as a warning, a `danger` action an agent could take without asking anyone (`agent-confirm`). A tree that passed before can now fail on the first two.

### Documentation

- The docs site switches icon set from Preferences (Phosphor by default, 16 sets written with `skryensya icons`), so every page shows the same components drawn by another library.

- Every install command in the docs installs from the release tarballs, with the Skryensya packages each one depends on, and says that npm publication starts with v0.1.0.

### Workarounds consumers can delete

- The `!important` position/transform/inset override on `.sk-megamenu__positioner`: use `data-anchor`, `data-match-width` and `data-offset`.
- `.sk-tooltip__positioner.sk-anchored { position: absolute }` and `.sk-menu > .sk-menu__positioner.sk-anchored { position: absolute }`.
- The `svelte/internal/flags/legacy` import before mounting, and the `svelte` resolver condition (or the Svelte plugin) added for the vanilla layer.
- A hand-written focus reveal for Marquee (`data-fade` plus the animation timeline).
- Restoring `--radius-control` on menu positioners in a pill-control theme, and the tab trigger border and selected-background overrides (use the new hooks).
- A marquee cadence set by hand in `ms`.
- `grid-template-columns: minmax(0, 1fr)` on `.sk-tabs`, `flex: none` on `.sk-footer`, `font-size` on `button.sk-nav-list__link`, `position: relative` on a focused skip link, and a hand-set `max-block-size` on `.sk-menu__content` (use the hook).
