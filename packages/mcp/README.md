# @skryensya/mcp

The MCP server of skryensya/ui. An agent describes the UI it needs, picks signatures, proposes the
composition as a **usage tree**, and receives the emitted code for both bindings. It never types kit
markup, so what was validated and what gets written cannot come apart.

```
product intent -> agent reasoning -> usage tree -> validate_ui (deterministic) -> Vanilla / React / CSS
```

The agent interprets intent. Everything this server answers is deterministic: the same artifact and
the same input give the same bytes, and only `validate_ui` decides whether a tree is valid.

## Tools

<!-- tools:start (generated by `pnpm --filter @skryensya/mcp docs`, do not edit) -->

| # | Tool | What it returns |
|---|---|---|
| 1 | `discover_ui` | Narrows the catalogue to candidate signatures, each with the evidence that matched it. |
| 2 | `get_examples` | Established example trees: the index with no id, one full tree with an id. |
| 3 | `get_contract` | One family's contract: options, slots, constraints, accessibility and CSS. |
| 4 | `validate_ui` | Validates a usage tree; when valid, returns Vanilla markup, React source, data module and CSS. |
| 5 | `get_catalog` | The exhaustive catalogue, paged: every family and signature with useWhen and avoidWhen. |

<!-- tools:end -->

The usual path is `discover_ui` -> (`get_examples` when a related example fits) -> `get_contract`
-> `validate_ui`. `get_catalog` is the exhaustive list: the fallback when discovery finds nothing
that fits, and still the authority on what is published. Neither a full catalogue read nor an
examples call is mandatory any more ([ADR-0026](../../docs/decisions/0026-deterministic-discovery-narrows-the-catalogue.md)).

Every result carries `schemaVersion` and `sourceHash`, errors included, so any answer can be traced
to the artifact that produced it.

## Discovery is lexical, and says so

`discover_ui` narrows about two hundred signatures to a candidate set. It compares the words of a
`query` (and whole `intents` terms) with compiled fields: signature id, contract id, intent,
category, `useWhen`, `alternatives`, `avoidWhen`. Each candidate carries `matched`, the exact field,
term and value that admitted it, plus its `useWhen`, `avoidWhen` and related example ids. There is no
score. Candidates are ordered by written rules:

1. more distinct terms matched in a naming field (signature, contract, intent, category);
2. then more distinct naming fields matched;
3. then more distinct terms matched in any field but `avoidWhen`;
4. then more distinct terms matched at all;
5. then catalogue order.

A match only in `avoidWhen` still counts, on purpose: "this is exactly what that signature is not
for" is how an agent reaches the alternative that is. `coverage` is `complete`, `partial` (a term
matched nothing, or `limit` cut candidates), `none`, or `browse` (no input: the intent vocabulary
and hosts are returned instead). On `none` or `partial`, the guidance points at `get_catalog`.

It is not semantic search and does not pretend to be. There is no model, no embedding and no
external service in this server.

## A tree has four fields, and they are not the same thing

```jsonc
{
  "contract": "nav-list",
  "signature": "NavListLink",
  "options": { "href": "/", "current": true },  // declared by the signature, mapped to attributes
  "attrs":   { "id": "home" },                   // passed to the host element as-is
  "slots":   { "trailing": "12" },               // named content, or a collection of {options, slots}
  "children": "Home"                             // the children slot, written directly
}
```

An option the signature does not declare is **rejected**, not ignored, and the message names the
sibling signature that does take it, because the mistake is almost always the wrong signature.

## Results

Each tool declares an `outputSchema`, returns its value as `structuredContent`, and the SDK
validates it before it leaves the server. The same value is also serialized as JSON in the first
text block, which is what clients that predate structured output (and every client of the previous
server) read.

Arguments that do not fit a tool's input schema come back the same way: an error result with
`schemaVersion`, `sourceHash`, and a `detail` naming the path at fault. Tree nodes are strict, so a
misspelt key (`option` for `options`) is rejected rather than silently dropped.

`validate_ui` on an invalid tree returns `valid: false`, the problems, and `emitted: null`: nothing is
emitted from an invalid tree. On a valid tree it returns the Vanilla markup, the React component,
`reactData` (a second file to write beside it when the composition has a collection), and `css`,
every stylesheet the composition needs as computed by `sheetsForTree` in `@skryensya/ai-compiler`.

## Architecture

```
src/index.ts, src/http.ts        transports (stdio, stateless Streamable HTTP)
src/create-server.ts             one server factory for both
src/tools.ts, src/schemas.ts     the tool inventory and the wire schemas (zod)
@skryensya/ai-compiler/agent     the deterministic service: catalogue, contracts, examples,
                                 discovery, validation + emission + stylesheet closure
```

This package is a protocol adapter ([ADR-0027](../../docs/decisions/0027-the-mcp-is-a-stateless-adapter-over-sdk-v2.md)). The knowledge it used to hold (a tree walker, a stylesheet
resolver that missed `hookSheets` and `compose[].sheets`, the example index) lives in the compiler,
where another frontend can use it too.

## Running locally

```bash
pnpm --filter @skryensya/ai-compiler build   # writes artifacts/ai-{index,manifest}.json
pnpm --filter @skryensya/mcp build           # bundles dist/index.js and dist/http.js
```

stdio, what `.mcp.json` starts:

```jsonc
{ "mcpServers": { "skryensya-ui": { "command": "node", "args": ["packages/mcp/dist/index.js"] } } }
```

Streamable HTTP:

```bash
pnpm --filter @skryensya/mcp start:http      # http://127.0.0.1:8787/mcp
```

Both speak the 2026-07-28 protocol and fall back to the 2025 handshake for older clients, through
the MCP TypeScript SDK v2 (`serveStdio`, `createMcpHandler`). HTTP is stateless: a fresh server per
request, no sessions, so `GET` and `DELETE` on `/mcp` from a 2025-era client answer `405`.

## HTTP configuration

| Variable | Default | Meaning |
|---|---|---|
| `HOST` | `0.0.0.0` when `NODE_ENV=production`, else `127.0.0.1` | Listen address. |
| `PORT` | `8787` | Listen port. |
| `NODE_ENV` | | `production` changes the `HOST` default. |
| `MCP_HTTP_TOKEN` | unset | When set, `/mcp` requires `Authorization: Bearer <token>`. |
| `MCP_ALLOWED_HOSTS` | localhost names on a loopback bind, none otherwise | Comma-separated hostnames the `Host` header may name. Unset on a public bind: not checked, so set it in production. |
| `MCP_ALLOWED_ORIGINS` | localhost names | Comma-separated hostnames a browser `Origin` may come from. Requests with no `Origin` (every non-browser client) pass. |
| `MCP_MAX_BODY_BYTES` | `1000000` | Largest accepted request body; larger answers `413`. |

`GET /healthz` answers `{"status":"ok"}` without auth and without touching the catalogue. The
artifact is loaded and verified at startup, so a process that answers it can serve.

Errors to remote clients never include a stack trace; details go to the server log (stderr). In
stdio mode nothing is ever written to stdout except protocol messages.

## Authentication

Local stdio needs none: whoever can start the process can use it.

Over HTTP the tools are read-only over public, non-secret data, so an unset `MCP_HTTP_TOKEN` is a
legitimate choice for a public server. Set it for a private or internal deployment; every `/mcp`
request then needs the token, and a missing or wrong one gets `401` with a `WWW-Authenticate: Bearer`
challenge. Never commit the token; set it as a secret in the deployment's environment.

The token is checked through the SDK's bearer machinery (`verifyBearerToken` with a verifier), so
standards-based MCP authorization is a replacement of that verifier with one that validates OAuth
access tokens, plus the SDK's `oauthMetadataResponse` for the protected-resource metadata. There is no
authorization server here and none should be written: use an existing identity provider.

## Deploying with Docker on Dokploy

`Dockerfile.mcp` at the repository root builds the image. The **build context is the repository
root**, not `packages/mcp`: the server bundles workspace packages and reads the compiled artifacts,
and neither exists from `packages/mcp` alone. The build stage runs, in order:

```bash
pnpm install --frozen-lockfile --offline      # after `pnpm fetch`, against the committed lockfile
pnpm --filter @skryensya/ai-compiler build    # writes artifacts/ai-{index,manifest}.json
pnpm --filter @skryensya/mcp build            # bundles dist/http.js
```

The runtime stage holds only the bundle, the artifacts and the four external npm dependencies at
the exact versions the lockfile resolved. It runs as the unprivileged `node` user with
`NODE_ENV=production`, `HOST=0.0.0.0`, `PORT=8787`, and a Docker `HEALTHCHECK` on `/healthz`.

In Dokploy, create an **Application**:

1. Source: this repository and branch. Build type **Dockerfile**, Dockerfile path `Dockerfile.mcp`,
   build context (docker context path) `.`.
2. Environment:

   ```
   MCP_ALLOWED_HOSTS=<your-domain>   # the public hostname, checked against the Host header
   MCP_HTTP_TOKEN=<secret>           # only for private access
   ```

   Never put the token in the repository or the Dockerfile.
3. Domains: add `<your-domain>`, container port `8787`, HTTPS on (Let's Encrypt). Dokploy's Traefik
   terminates TLS and forwards to the container.
4. Deploy. Dokploy waits for the container's health check before routing to it, and stopping a
   container sends SIGTERM; the server drains in-flight requests for up to 10 seconds.

The public endpoint is:

```
https://<your-domain>/mcp
```

To reproduce the image locally:

```bash
docker build -f Dockerfile.mcp -t skryensya-mcp .
docker run --rm -p 8787:8787 -e MCP_ALLOWED_HOSTS=localhost skryensya-mcp
curl http://localhost:8787/healthz
```

Test the deployment with the MCP Inspector:

```bash
npx @modelcontextprotocol/inspector
```

Choose transport **Streamable HTTP**, URL `https://<your-domain>/mcp`, and, when a token is set, add
the header `Authorization: Bearer <token>`. Connect, list tools, and call `discover_ui` with
`{"query": "switch"}`. If you use the Inspector's direct (browser) connection instead of its proxy,
add the Inspector's hostname to `MCP_ALLOWED_ORIGINS`.

The server is stateless, so more than one replica needs no sticky sessions.

## Why it is bundled

It is the only package in this repository that is an **executable**. The others export TypeScript
and leave compiling to their consumer; this one is started by plain `node`, which cannot load a `.ts`
file or follow a workspace link. The bundle collapses the chain (`ai-compiler` -> `core` ->
`snippets`) into one file. The MCP SDK, `hono` and `zod` stay external because they are real npm
dependencies.

`SK_ARTIFACTS` changes where the compiled artifacts are read from. The server never falls back to
reading source.
